授权与激活

CTF-BTFly 使用离线、设备绑定的签名许可证：程序不连接授权服务器，导入一份与本机设备码匹配的 .ctflic 文件即可进入工作台。本页只讲使用者需要做的三步，以及出错时怎么判断。

离线校验，不联网验证 许可证与设备码绑定 导入后无需重启

HOW IT WORKS

为什么需要授权，它校验的是什么

授权只解决一件事：确认这份软件运行在获得许可的那台机器上。它不上传你的数据，也不跟踪使用行为。

离线签名，无需联网

许可证是由授权方使用私钥签发的 JSON 文件，扩展名为 .ctflic。程序内置公钥做验签，因此校验过程完全离线。

Ed25519 签名 · 本地验签

设备绑定，不含硬件信息

设备码由系统机器标识与系统盘卷序列号派生为 SHA-256 摘要，原始标识不会写入许可证，也不会显示在界面上。

SHA-256 · 128 位显示标识

改一个字节就失效

许可证内容可读，但任何字段被修改都会导致签名校验失败；换到另一台机器则设备校验不通过。两者都由本地控制平面判定。

签名 / 设备 / 产品 / 有效期

THREE STEPS

三步完成激活

未授权时工作台会停在「设备授权」页，只保留健康检查、授权状态、许可证导入与安全退出可用。下面三步全部在这一页完成。

  1. STEP 01

    读取本机设备码

    在锁定页找到「本机设备码」区块，点击「复制」。设备码形如 BTF1-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XX。

    BTF1-XXXX-…-XX
  2. STEP 02

    提交给授权联系人

    把设备码发送到下方「授权联系」中的渠道，说明使用场景（比赛、靶场或研究）与需要的期限，等待授权方签发 .ctflic 文件。

    QQ 群 921416626
  3. STEP 03

    导入离线授权文件

    回到锁定页的「导入离线授权文件」，点击「选择授权文件」并选中收到的文件。校验期间按钮显示「正在验证」，通过后立即进入主界面。

    无需重启

AFTER ACTIVATION

已授权之后：查看、更换与删除

激活后进入 应用设置 → 设备授权，可以核对当前实际加载的授权文件与签名元数据，而不必猜「是否已经生效」。

字段含义
状态与客户校验结果、客户名称与授权版本；校验失败时该区块显示失败原因
许可证 ID授权方签发时写入的标识，便于核对与追溯
本机设备码当前设备的设备码，与许可证绑定的值应当一致
签发时间许可证的签发时刻
到期时间许可证到期时刻；未设置期限时显示「永久有效」
授权功能签发时写入的功能标识，用于区分授权范围
当前授权文件实际加载的文件路径，可一键复制；也可展开查看原始文件内容

更换授权文件

点击「选择并更换授权文件」。新文件会先校验签名、设备与有效期，校验失败不会覆盖当前授权，可放心试。

先校验后替换

删除授权

点击「删除授权」并二次确认后，应用立即回到激活页，任务、模型网关与 Agent 执行同时锁定。重新导入有效许可证即可恢复。

不可撤销 · 需重新导入

文件存放位置

默认落在当前用户的应用数据目录：%LOCALAPPDATA%\CTF-BTFly\licensing\sandbox\license.ctflic。受控的便携部署也可以把许可证放在程序同目录。

便携路径 · 需人工放置

WHEN TO REISSUE

什么时候需要重新申请许可证

设备码是设备身份与系统盘的摘要，因此下面这些操作会让设备码变化，旧许可证随即不再匹配——这是设计如此，不是「授权丢失」。

情形现象处理
重装 Windows设备码变化，提示设备不匹配用新设备码重新申请许可证
克隆或更换系统盘设备码变化，提示设备不匹配用新设备码重新申请许可证
修改系统身份信息设备码变化，提示设备不匹配用新设备码重新申请许可证
许可证到期提示有效期校验不通过联系授权方续期或签发新许可证
使用了旧版本许可证提示版本或产品不匹配历史 Docker 版许可证不能用于当前 Windows 沙箱版，需按当前版本重新签发
换了另一台机器设备不匹配每份许可证只对签发时的设备码有效，换机需单独申请

IMPORT ERRORS

导入失败对照

激活页会把失败原因直接写在导入按钮下方。以下是常见提示、成因与处理方式。

界面提示成因处理
请选择 .ctflic 授权文件。文件扩展名不是 .ctflic，例如被聊天工具改成了 .txt确认扩展名后重新选择；不要用压缩包内的预览文件
授权文件必须为不超过 64 KiB 的非空文件。文件为 0 字节，或被套上了额外内容让授权方重新发送原始 .ctflic，不要编辑或另存
验签失败 / 签名无效文件被修改过，或不是授权方签发的文件重新获取原始文件；任何字段修改都会导致验签失败
当前授权文件绑定了另一台设备，请使用下方设备码重新申请。许可证绑定的设备码与本机不一致复制本页设备码重新申请；重装系统或换盘后尤其常见
产品 / 版本不匹配用了历史 Docker 版或其他版本的许可证按当前 Windows 沙箱版重新签发
许可证已过期到期时间早于当前时间联系授权方续期，或改用长期许可证
无法访问剪贴板，请手动选择并复制设备码。浏览器或系统拦截了剪贴板写入手动选中设备码文本复制，效果相同

先确认一件事：许可证是否真的没生效。打开「应用设置 → 设备授权」看「当前授权文件」路径与到期时间，比反复重试导入更快定位问题。

仍未解决时，把设备码、许可证 ID 与界面提示原文一起发到授权联系渠道，不要发送许可证文件本身。

BOUNDARY

授权边界

把边界说清楚，比事后解释省事。以下四点是使用许可证时的硬约束。

签发由授权方完成

许可证必须由持有私钥的授权方离线签发。站点不提供、也不分发任何签发工具，因此不存在「自己生成一个许可证」的路径。

一份许可证对应一个设备码

许可证与签发时的设备码严格绑定，复制到其他机器无法通过校验。因此设备数量需要按实际使用单独申请。

不要公开许可证与设备码

许可证本身不含密钥，但仍属于个人授权凭证。对外反馈问题时提供许可证 ID 即可，不要贴出完整文件或设备码。

仅限授权范围使用

适用于获得明确授权的 CTF、靶场与安全研究。请勿扫描、攻击或导入未获授权的目标，详见 常见问题 中的数据与授权条目。
