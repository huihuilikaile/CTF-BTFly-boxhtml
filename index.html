RELEASE 2.9.5

2.8 → 2.9 的关键新增

从 2.7.9 到 2.9.5，变化的不是界面皮肤，而是「更新怎么到位」「题目从哪来」「工具从哪装」这三件长期拖慢工作流的事。下面四项都已进入当前测试版。

01应用内在线更新

设置 → 关于 → 在线更新。启动后自动首查，此后每 6 小时检查一次，也可手动触发。

  • 清单用 Ed25519 签名，客户端内置公钥验签，验签失败一律拒绝更新
  • 安装包按清单的 SHA256 与字节数逐一校验，不匹配即删除，不留半成品
  • 替换失败自动回滚到更新前状态，并保留现场快照供排查

02平台题目接入

AI 题目管家按平台形态选择建题链路，把「谁负责启动靶机环境」这件事明确下来。

  • 提供 HTTP Open API 的平台，由工作台建题时启动容器并写入访问地址
  • 只提供 MCP 工具的平台，由管家在建题前调用启动工具并轮询到地址
  • 平台容器配额满额时登记待补题并按 45 秒间隔重试，最多 8 次，不再静默停止

03统一对话栏双模式导入

对话式建题与比赛 API 批量导入合并到同一条入口，由意图路由判断走哪条路。

  • 单题可按对话补充题面、目标、Flag 格式与附件
  • 接入比赛 API 后可批量导入题目并逐题启动，遵守本机调度容量
  • 附件走安全落盘与去重，Flag 提交流程保持人工确认

04工具链扩展成三条通道

Windows 基础工具、WSL 工具与受管 Python 依赖各自独立，互不替代。

  • WSL 基础工具在发行版内以独立隔离环境运行，普通任务按需调用
  • 受管 Python 依赖在隔离目录构建固定版本 wheel，重启时原子发布
  • 发布模板附带 25 项 Windows 与 19 项 WSL 示例条目，可用 AI 辅助扫描本机目录生成配置

完整能力与版本对比见 功能全景；从 Docker 版或 1.3.1 迁移时的差异也集中在那里。
