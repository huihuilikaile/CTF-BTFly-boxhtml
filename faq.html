安装与启动

只复制 CTF-BTFly.exe 到别的目录能运行吗？

不能。主程序只是桌面外壳，同目录还需要本地控制平面、沙箱 Broker 与 Runner、更新进程、随包运行文件以及 theme/、defaults/ 等资源目录。

正确做法是完整解压发布包，并把整个目录放在当前用户可写、路径较短的新位置；不要只挑单个可执行文件复制。

首次启动卡很久，是卡死了吗？

通常不是。首次启动会在程序旁创建 data/ 并初始化工具资产，首次需要复制的工具资产体量较大，耗时长属正常现象；初始化完成后，后续启动会复用，明显变快。

若长时间没有进展，先确认程序目录完整（defaults/ 与随包运行文件都在），再看 data/daemon.log 是否有明确报错。

Windows 提示「未知发布者」或被 SmartScreen 拦截，怎么办？

当前版本未做 Windows 代码签名，因此首次运行会触发 SmartScreen 提示，需要手动选择「仍要运行」放行一次。通过应用内在线更新替换的文件通常不再触发该提示。

请只从可信渠道获取发布包，并核对随包的 .sha256 校验值；不要为了「省事」关闭系统安全策略。

再双击一次没有打开第二个窗口？

这是设计行为：同一个数据目录只允许一个桌面实例。再次双击会把已有窗口恢复到前台并退出新进程，避免两个实例同时写数据库。

另外，关闭桌面窗口并不会结束后台控制平面，所以重新打开应用通常是复用已有进程，而不是重新启动一次。要彻底重启，请先在托盘退出程序。

购买与设备授权

怎么购买？开通码是什么？

在官方店铺购买「BTFly 授权」商品，拍下后自动发货，发货内容只有一串一次性开通码，不含任何下载链接。开通码用于在授权助手中注册授权账号，用过即失效。

店铺入口与购买咨询可在 QQ 群 921416626 获取；商品页的「使用说明」里有授权助手与软件本体的下载地址，以及图文步骤。

授权助手在哪里下载？

授权助手与 CTF-BTFly 软件本体的下载地址，都写在购买商品的「使用说明」中，发货内容里不含链接。

找不到或链接失效时，到 QQ 群 921416626 反馈，不要从第三方来源下载可执行文件。

设备码在哪里看？

未授权时工作台会停在「设备授权」页，页面中的「本机设备码」区块就是设备码，点击右侧「复制」即可。已授权后也可以在 应用设置 → 设备授权 查看同一份设备码。

设备码形如 BTF1-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XX，它只是机器标识与系统盘卷序列号的摘要，不含原始硬件信息。完整流程见 授权与激活。

授权有效期多久？到期怎么续？

授权助手自助生成的授权单次有效期为 30 天。到期后不会丢失任何数据，软件只是回到「设备授权」页并锁定任务、模型网关与 Agent 执行。

续期是自助动作：打开授权助手，在当前账号内手动续期，重新导出 .ctflic，再到 应用设置 → 设备授权 点击「选择并更换授权文件」替换即可。

导入许可证后需要重启软件吗？

不需要。校验通过后工作台会立即进入主界面，并开始调度此前待启动的任务；续期后更换授权文件同样不需要重启。

重装系统或换了硬盘，为什么原来的授权不能用了？

授权绑定的是生成时那台机器的设备码，而设备码由系统机器标识与系统盘卷序列号派生。重装 Windows、克隆或更换系统盘、修改系统身份都会让设备码变化，旧授权随即不匹配。

这属于设备变更，需要联系管理员处理，不要自行重复注册新账号。

想换一台电脑，授权能带过去吗？

不能直接复制过去：授权文件与设备码严格绑定，拿到另一台机器上会提示「当前授权文件绑定了另一台设备」。

更换设备属于设备变更，请联系管理员办理；对外的反馈与申请统一走 QQ 群 921416626，不要尝试修改授权文件内容。

能不能完全离线使用？

授权环节可以完全离线：授权文件是本地文件，程序内置公钥验签，不连接任何授权服务器，也不会上传使用数据。

需要注意「离线轻量」只影响本地模型与精简 Agent 策略，沙箱的网络范围是独立配置项；要访问在线模型或联网靶机时仍需网络。

授权文件丢了或误删了怎么办？

不需要重新购买。在授权助手的原账号内重新导出 .ctflic 即可，它仍然绑定同一设备码。

如果在软件内误点了「删除授权」，应用会立即回到激活页，重新导入有效授权文件即可恢复。

模型配置

模型请求返回 403？

先核对三处：Base URL 是否写成完整的接口前缀、协议是否与目标服务一致、是否需要额外的 User-Agent。然后确认该 Key 对目标模型有调用权限、未触发限流。

可在「系统概况 → 模型连接」单独检测该模型，避免把配置问题误判成任务问题。

只用本地模型可以吗？

可以。在线与本地 OpenAI-compatible 模型都可接入，本地部署时把 Base URL 指向本机服务即可。

如果使用黑板或超级模式，需要准备多个不同模型：调度模型与 Worker 模型不能重复，Worker 之间也不能重复。

沙箱与工具

Windows 沙箱一直显示 preparing 或 unavailable？

preparing 表示 Broker 正在准备共享目录权限，此时设置页可用，但任务创建入口会保持禁用；成功后自动进入 ready。

若停在 unavailable：确认首次 Broker 准备时弹出的 UAC 请求已同意、程序目录完整（Broker 与 Runner 都在）、设置页给出的结构化错误指向哪里。unavailable 是可重试状态，不需要重装。

命令报 Could not resolve host？

说明该任务的网络范围不允许访问目标。把题目的网络范围改为「默认（公网与局域网）」，然后停止旧任务并重新配置启动。

修改网络范围不会影响已在运行的任务，必须重新配置或重试才生效。

日志出现端口 bind 10013 或 address already in use？

bind 10013 通常是端口被系统保留或权限不足。确认四个可执行文件来自同一个发布包，并完全结束残留进程后重启；正常回退时日志会给出实际使用的端口。

address already in use 表示端口已被占用，需要退出残留的控制平面进程或处理占用方，不会自动换端口。

受管 Python 依赖构建失败，或一直停在「等待发布」？

构建失败先看两条：依赖是否写成精确的 package==version（不要用范围或 latest），以及该版本是否提供 CPython 3.12 x64 的 wheel；同时填写正确的实际导入名。

「一直等待发布」表示产物要在完全重启后才原子发布。请彻底结束桌面端、控制平面、Broker、Runner 与任务进程后重新启动。

基础工具检测会帮我下载安装工具吗？

不会。基础工具检测只读取你选择的目录与 JSON 清单，不下载、不安装、不更新任何程序，也不会执行包管理器命令。

唯一的例外是「受管 Python 依赖」：只有你明确确认构建时，才会在隔离目录内安装固定版本依赖，成功产物在重启后发布。

在线更新

提示「当前版本未启用在线更新」？

该构建未内置更新公钥，或本地控制平面版本过旧。使用完整发布包手动覆盖升级一次后即可恢复该入口。

点「立即更新并重启」之后没有反应？

先看 data/.update/updater.log。如果日志出现「等待进程退出超时」，说明应用并没有真正退出——最常见原因是有任务正在运行。

更新前需要让所有任务结束；应用常驻托盘，也可以在托盘里先选「退出程序」再重试。

更新后版本没变，或者更新失败，会弄坏程序吗？

替换过程中任何文件写入失败都会整体回滚到更新前状态，并在 .update/rollback-<时间戳>/ 保留被替换文件的原始副本，同时日志会记录本次替换了多少文件。

确认新版本稳定后可以手动清理回滚目录；排查时先读 updater.log，再对照回滚目录。

能通过在线更新降级到旧版本吗？

不能。客户端只接受版本号高于当前版本的清单，因此在线更新不做跨版本降级。

确需回退时，用旧版完整发布包手动覆盖同名文件；data/ 目录、自装 Skill 与许可证不会被覆盖。

数据与隐私

data/ 目录里有什么？
  • 任务、事件、黑板、模型用量与 MCP 注册表数据库
  • 连接信息与本地鉴权令牌（含敏感信息，不要外发）
  • 题目工作区：附件、Artifact 与 WRITEUP.md
  • 工具包、基础工具配置、受管 Python 运行时
  • 用户提示词副本与自装 Skill
  • 在线更新的下载缓存、日志与回滚快照

默认位置是程序旁的 data/，也可以通过环境变量指向其他绝对目录。

改了数据目录，旧任务为什么不见了？

切换数据位置只改变下次启动使用的路径，不会在线移动或复制旧数据。切到一个空目录后旧任务自然不显示，但数据仍完整保留在原目录，切回原路径即可再次访问。

需要迁移时：确认没有运行中的任务并完整退出，备份旧目录，把旧的数据库与整个工作区目录复制到新位置，再启动确认题目、附件与 Writeup 都可访问。验证完成前不要删除旧目录。

哪些内容绝对不能上传或外发？

模型 API Key 与凭据文件、许可证文件、比赛附件与 Flag、题目工作区与 data/ 目录整体，以及运行日志中的本机路径段。

反馈问题需要提供信息时，优先给出许可证 ID、界面提示原文与脱敏后的日志片段。
